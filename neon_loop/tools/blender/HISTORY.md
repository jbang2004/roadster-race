## 设计语言

* Cybertruck 式的未来简约：**大平面 + 少量清晰的折线**。面与面相交成利落的棱（倒角半径约 5–15 mm，全车一致），
  面内不允许鼓包、凹坑、扭曲；高光/反射线在平面上是直的，在曲面上是单调平滑的弧。
* 全车只有十几条“主线”，每条都有清楚的起点、终点和走向逻辑；灯、缝、侧标等细节都挂在主线或主线交点上。
* 例外只有两处是圆润体量：**前轮上方的前翼子板包络**（003：绕轮的平滑圆弧；U 在其上方成一道拱，L 在轮口处被切断，见下「用户更正」）和**玻璃罩**（侧视弧顶）。

## 主线（按逻辑）

**侧面两条线，永不相交（R1c「用户更正」，取代 R1/R1b 的 L1 两段式说法）**

两条线都从**车头上前角 N**（灯带端点，约 x -2.39, |y| 0.67, z 0.545）出发，之后分开，再也不会合并。N 之后 U 总在 L 上方。

**U ＝ 翼子板顶棱 → 腰线 L2（一条线）**
* 起点 N → **一道圆拱越过前轮**（018：前翼子板体量的上轮廓：x -2.20 z 0.64，-2.00 z 0.735，-1.80 z 0.81，-1.60 z 0.862）→ **A 柱根**（玻璃下角 A_OUT，约 x -1.43, |y| 0.927, z 0.876）。
* 过 A 柱根**不折**，直接成为侧窗玻璃的**下沿 L2（腰线）**：A 柱根到门前缘几乎水平（z 0.874 @ x -1.0，0.872 @ -0.4），之后越往后越陡地上扬（0.930 @ 0.15，1.000 @ 0.65，1.040 @ 0.9）→ **窗尖** T（约 x 1.2, |y| 0.64, z 1.19）。
* 俯视：N 的 |y| 0.67 → 在 x -1.75 处到最宽的平台 0.935（过前轮的拱顶），之后向内收：0.917 @ -0.4，0.885 @ 0.15，0.825 @ 0.65，窗尖 0.64。
* 是**一条清晰的线，带亮的高光边**（上面是翼子板顶/肩面，下面是侧面）；全长是 11 个控制点的 B 样条拟合，最后 0.40 m 换成一段 G1 Hermite 弧，让 U 以肩面的切平面到达窗尖
  （原先 24° 的折，现为 ≈1°）。侧视曲率只有一个拐点（窗尖处），没有波纹。
* 在 018 / 017 / 016 上的叠线：`shots/full_rework/r1c/lines/`（红＝U，青＝L）。

**L ＝ 车身特征线（一条线）**
* 起点同样是 N → 一条**平缓、近乎直、单调上升的曲线**一路向后。**前轮开口把它切断**（线仍是同一条曲线，只是轮拱处没有金属）；
  在轮后的**黑色刀片侧标**（x -1.22…-0.89，前端琥珀灯）处重新出现 → 沿**门顶**向后 → 终点＝尾部唇边外端角（约 x 2.41, |y| 0.92, z 1.00）。
* 前后两段**在侧视里落在同一条光顺曲线上**：前段是 018 上描的色调边（x -2.39…-1.86，z 0.545 → 0.65，已抬 9 mm 使其精确起于 N），
  后段沿用 R1b 的拟合 z = 0.834 + 0.103 x − 0.0026 x²（x -1.2…1.65，误差 < 2 mm），尾部 (2.05, 1.025) → (2.41, 1.00)。
* 俯视：N 0.67 → 倒角过鼻 → x -1.625 起是最宽的直线 |y| 1.06（x -1.625…1.65）→ 尾部收到 0.92。9 + 10 个控制点的 B 样条；侧视和俯视曲率**都没有拐点**（最大曲率 0.65 / 1.33 1/m）。

**U 与 L 之间的面**
* **前面：翼子板侧面（透镜）**：从 N 到 A 柱根的一块鼓起的面（外鼓最大约 6 mm，沿宽度渐入、沿 x -0.9…0.3 渐隐，更大的鼓包会在镜面检查里出现涡旋）。
  翼子板顶面（fender_top）从引擎盖面出发与引擎盖 **G1 相切**（沿 L5），翻过 U。
* **轮后：肩带（shoulder）**：夹在 L2 与 L 之间，**向后越来越宽**（A 柱根处 ≈0 → 门前缘约 38 px → x 1.1 处约 45 px），向内倾（tumblehome）；
  到窗尖后接后肩面（rear_shoulder，与肩带 G1 相切，肩带|后肩面的二面角 ≈1°），再到尾翼两侧的棱脊（L10）。
* **L 以下**：前角斜面（L6）和下翼子板；轮后是门平面（门与后翼子板一整块近乎竖直的大平面，下到 L3）。

**L3 下部黑区上沿**：车身下部是黑色楔形区（亮黑/碳纤），上沿是一条斜直线：前轮后方约 (x -1.09, z 0.29) → 后轮前方约 (x 1.20, z 0.52)。
后轮后方整个下后角都是黑色，一直到尾灯带下方。门槛（rocker，碳纤，003）在黑区内。

**L4 前脸上沿＝灯带**：一条连续的细白灯条，从车头一角到另一角；正视中间略拱，俯视中间略前凸，两端在角上略向下弯。
灯带下方整个前脸是亮黑面板（约 0.10–0.12 m 高，略向后下倾），下面是黑色进气口和向前伸出的黑色薄扰流板（splitter，z ≈0.27）。
前脸下沿约 z 0.30。

**L5 引擎盖棱**：从灯带两端向后汇聚到挡风玻璃两下角的两条棱，围出中央的大梯形平面（略凸）。棱外侧是向外下倾的翼子板顶面，其外缘就是 U（翼子板顶棱）。
**角三角面**：L4/L5/U/L 交汇的车头上角 N被一块小三角折面削掉（俯视 013 / 近景 005 清楚可见，约 x -2.26…-2.02）。

**L6 前角斜面**：灯带端点以下、黑色前脸外侧，是一块白色斜切大平面（前翼子板的前面），从灯带端点向下向后过渡到前轮拱前方。

**L7 引擎盖缝**：俯视在 x ≈ -1.81 有一条贯穿的横缝（前备箱盖后缘），其后到挡风玻璃下沿（x ≈ -1.63）是一条窄的 cowl 条。

**L8 玻璃罩**：俯视为拉长的六边形：前缘横直（挡风玻璃下沿），两侧在 A 柱处外折（**「用户更正」** 外缘是车身色的 A 柱 / 边梁，玻璃在两根边梁之间），沿车门向后，后段收窄成梯形后窗，

## 当前模型（r0）与实车的差异

1. 前脸：两段分离的矩形白色 DRL，白色方盒式前脸 → 应为一条连续灯带 + 黑色前脸 + 白色前角斜面。
2. 引擎盖：中间有一块凸起的矩形面板 → 应为平整大平面 + 两条汇聚棱 + 横缝 + 角三角面。
3. 前翼子板：圆鼓包，U（顶棱）与 L 不清楚。
4. 侧面：L 软且断续，肩面与门面的交界模糊。
5. 下部：浅灰色门槛台阶 + 黑色内凹 → 应为 L3 黑色楔形区。
6. 车顶后段：顶棚后有暗色 Trim 横条，侧视有凹陷/台阶 → 应为直线 fastback，后窗一直延伸到尾翼缝。
7. 尾翼：收起时是落在黑色凹槽里的窄板 → 应为与车尾面齐平的整块车身色面板，只留一条缝。
8. 车头长度：侧视比实车短约 0.05–0.10 m（以 p016 / p013 叠图确认）。
9. 表面质量：前翼子板、后肩、尾部等处有 warp 产生的软鼓包。

## 方案（R1c：面片外壳 shell2.py；R1b 的笼子外壳保留为 `--shell-v1`，验收前不删）

R1b 的 Catmull-Clark 笼子在镜面检查里一直有褶皱（A 柱根、鼻角、后肩），根子在“从一个粗笼子细分出全部曲面”。R1c 换了造面方法，其余基础设施
（build_game_car 的挂接点、NEW_HIDE、内饰、后部部件、LOD、机位、工具、已测坐标）都不变：

* **曲线**（`design2.py` + `curves2.py`）：每条特征线都是控制点很少的**光顺 3D 样条**（实测点的最小二乘 B 样条拟合 / 该直就直的直线 / Hermite 过渡），
  并做曲率检查（拐点数、最大曲率；`curveplot.py` 出图，`shots/full_rework/r1c/curves_U_L.png`）。曲线是面片之间**唯一的耦合**。
* **边注册表**（`shell2.py` 的 `EDGES` / `Registry`）：每条共享边采样一次（对齐全局站位表 XS），相邻面片**逐点共用**同一条边 → 滴水不漏（无 T 接、无碎片），
  面片都止于真实的角点（`snap` 3 mm 容差）。
* **面片**：每块面片是一个有名字的生成器 `p_xxx(R)`，是**它的边界曲线加自身参数的纯函数**，最后才合并：
  `front_face, hood, fender_top, shoulder, wall, wall_black, door_glass, pillar, rail_band, rear_shoulder, glass, ridge_inner, deck, tail_upper, tail_lower`（共 15 块，右半，左半镜像焊接）。
  做法是直纹带（每行等分数 `CONST_M`，尖端行收成一点）、Coons 片（引擎盖、前脸、尾面）、以及翼子板顶面的高度场（沿 L5 与引擎盖 G1 相切，翻到 U）。

## 2026-10-20 q5 第 3 项：分缝线断成虚线（已修）

- 现象：展厅近景里引擎盖缝 L7、L5 缝、角板缝断成点线和虚线；叶子板棱的轮廓发锯齿；喷口圆环有棱角。
- 先试过把缝线采样加密到 6 mm，结果更糟，排除了"弦线沉进漆面"的猜测（改动已撤回）。
- 用 `?rawcar` 加载未压缩的 .raw.glb，同一机位缝线完全干净。所以问题出在压缩导出，不在几何。
- 原因：Blender glTF 导出器的 meshopt 压缩把 POSITION、NORMAL 用指数滤波编码，尾数固定 12 位（`io_scene_gltf2/io/exp/meshopt.py` `EXP_FILTER_BITS`），每个顶点三个分量共用一个指数。离原点 2–4 m 的顶点因此落在 1–2 mm 的网格上。缝线带只比漆面高 0.7 mm，于是时隐时现。
- 修法：`build_game_car.py` `export_glb` 在导出前把 `EXP_FILTER_BITS` 设为 18（`--exp-bits` 可改），网格 ≤ 0.03 mm。解码端支持任意尾数位数，游戏代码不用改。
- 代价：car_hi.glb 1.76 → 2.27 MB，lod1 579 → 703 kB，lod2 107 → 128 kB；三角形、draw call 不变。外壳和各区域的构建日志与改前逐行相同。
- 已装进 public/assets/car（只换了三个压缩 glb，raw 和 meta 不变）。npm test、wingtest、carshots 通过，比赛画面正常。
- 备份：`../backup/gapfix_before/build_game_car.py`、`../backup/gapfix_assets_before/`；补丁：`shots/gapfix/export_bits.patch`；对比图：`shots/gapfix/z_{before,raw,exp18}_fl.png`、`z2_{before,exp18}_p016.png`。
